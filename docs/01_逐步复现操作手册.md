# 从零逐步复现操作手册

下面每一步都包含“在哪里、做什么、为什么、怎样保存、怎样运行、预期结果”。第一次不要跳步。

## 0. 软件选择

- 写 Python/Cypher/Markdown：VS Code。
- 阅读和导出项目：Typora。
- 执行命令：VS Code 下方 PowerShell 终端。
- 看图：浏览器打开 Neo4j Browser `http://localhost:7475`。
- 容器状态：Docker Desktop 只负责确认 Engine running；实际命令仍在 PowerShell 中输入。

## 1. 打开项目

VS Code 选择“文件 → 打开文件夹”，打开：

```text
./Day35_Day36_GraphRAG_Homework
```

打开终端后输入：

```powershell
Set-Location "./Day35_Day36_GraphRAG_Homework"
$env:PYTHONIOENCODING = "utf-8"
```

逐词解释：

- `Set-Location`：PowerShell 的“切换当前目录”命令。
- 引号中的内容：目标绝对路径。
- `$env:`：读写当前终端进程的环境变量。
- `PYTHONIOENCODING`：告诉 Python 控制台用什么字符编码。
- `utf-8`：能统一保存和显示中文的编码。

## 2. 安装依赖

```powershell
uv sync --python 3.12
```

- `uv`：Python 项目和依赖工具。
- `sync`：让虚拟环境与 `pyproject.toml`、`uv.lock` 同步。
- `--python 3.12`：明确选 Python 3.12。

预期：看到 `Resolved`、`Installed` 或无错误结束；项目出现 `.venv`。

## 3. 先运行不需要数据库的版本

```powershell
uv run python -m pytest -q
```

- `uv run`：在本项目虚拟环境中运行后面的命令。
- `python -m pytest`：用当前 Python 启动 pytest 模块，避免误用 Anaconda 的 pytest。
- `-q`：简洁输出。

预期：

```text
27 passed
```

再运行主程序：

```powershell
uv run python -m day3536_homework.main
```

预期推荐顺序：`P005、P001、P002`；高风险 `P003` 和高门槛 `P004` 不出现。

## 4. 启动真实 Neo4j + APOC + GDS

先确认 Docker Desktop 左下角或主界面显示 Engine running。然后在项目根目录：

```powershell
& ".\scripts\01_启动Neo4j_GDS.ps1"
```

- `&`：PowerShell 调用运算符，表示执行后面的脚本。
- `.\`：当前目录。
- `scripts\...ps1`：脚本相对路径。

预期末尾出现 APOC 与 GDS 版本；本次验证版本为 APOC `5.26.30`、GDS `2.13.12`。

浏览器打开：

```text
http://localhost:7475
```

连接地址选：

```text
neo4j://localhost:7688
```

本技术演示容器关闭了 Neo4j 登录认证，只监听本机映射端口，不用于生产。

## 5. 导入数据并运行全部 Cypher

```powershell
& ".\scripts\02_导入并验收Neo4j.ps1"
```

脚本依次执行四份文件。预期关键结果：

- `DAY3536_DATA_READY`
- Dijkstra：总成本 `3.0`，路径 `A站 → B站 → D站`
- PageRank：P002 排名第一（当前固定样例）
- Louvain：C001/C002 同社区，C003/C004 同社区
- 四个 PASS 字段都是 `TRUE`

Python 再验收一次：

```powershell
uv run python ".\tests\verify_neo4j_integration.py"
```

预期第一行：

```text
NEO4J_INTEGRATION_PASS
```

## 6. 启动并验证真实 Milvus 混合检索

首次运行需要下载官方镜像：

```powershell
& ".\scripts\04_启动Milvus.ps1"
```

脚本把 Milvus 2.6.17 映射到本机 `19531`。对象存储的临时凭据只在运行进程中生成，不写入项目。

然后运行：

```powershell
uv run python ".\tests\verify_milvus_integration.py"
```

预期：

```text
MILVUS_INTEGRATION_PASS
collection=day3536_bank_products_hybrid
inserted=5
safe_result_ids=['P005', 'P001', 'P002']
```

这里的流程是：文本 → 稠密向量；原始文本 → BM25 稀疏向量；两路各自检索；RRF 合并；表达式提前过滤风险和金额。

## 7. 保存与提交

1. 在 VS Code 中编辑文件后按 `Ctrl+S`。
2. 用 Typora 打开 `Day35&Day36作业_提交版.md`。
3. 把姓名、团队、日期替换为自己的信息。
4. 把自己运行时的 4 张截图插入对应位置：Neo4j 版本、Dijkstra、Louvain、Milvus 验收。
5. Typora 选择“文件 → 导出 → PDF”。
6. 按 `docs/06_提交清单.md` 逐项检查。

## 8. 停止服务但保留数据

```powershell
& ".\scripts\03_停止Neo4j.ps1"
& ".\scripts\05_停止Milvus.ps1"
```

这两个命令只停止容器，不删命名卷。不要使用 `down -v`，除非你明确想删除本项目数据库。
