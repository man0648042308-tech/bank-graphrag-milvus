# 核心概念逐词讲解

## 1. 图、节点、关系、属性

把 Neo4j 想成“人和东西之间的关系网”。

```cypher
MATCH (c:Customer)-[:PURCHASED]->(p:Product)
RETURN c.name, p.name
```

逐段解释：

- `MATCH`：匹配已经存在的图模式，类似“请帮我找”。
- `(c:Customer)`：一个节点；变量名是 `c`，标签是 `Customer`。
- `c` 可以自己取名，但后面引用时必须一致；`Customer` 是数据模型合同，不能随便改。
- `-[:PURCHASED]->`：一条有方向的关系，类型是 `PURCHASED`。
- `(p:Product)`：另一个节点，变量名 `p`，标签 `Product`。
- `RETURN`：把查询结果返回给调用者。
- `c.name`：读取 `c` 节点的 `name` 属性。

冒号 `:` 在 Cypher 中常用于“类型/标签”，后面不跟 Python 的缩进，也不跟 `{}`。花括号用于属性条件，例如：

```cypher
(c:Customer {customer_id:'C001'})
```

这里 `{}` 里面是“键: 值”的属性映射。

## 2. Dijkstra 最短路径

解决的问题：从 A 到 D 有多条路，哪条总成本最小？

示例边权：A→B=1，B→D=2，A→C=4，C→D=1。所以：

- A→B→D：1+2=3
- A→C→D：4+1=5

Dijkstra 选择成本 3 的第一条。它要求权重不能为负数。银行场景可以把“成本”换成距离、时间、手续费或风险代价。

关键配置：

```cypher
{
  sourceNode: source,
  targetNodes: target,
  relationshipWeightProperty: 'distance'
}
```

- `sourceNode`：起点。
- `targetNodes`：一个终点或终点列表。
- `relationshipWeightProperty`：从关系的哪个属性读取权重。
- `stream`：把计算结果临时返回，不写回数据库。

## 3. PageRank

PageRank 不是简单数入边。一个节点被“重要节点”指向，价值通常高于被许多低价值节点指向。计算过程会反复传播权重，直到分数基本稳定。

银行推荐中可用于：

- 产品共同购买图里的产品影响力；
- 客户转介绍网络里的关键客户；
- 交易网络中需要关注的中心账户。

限制：分数高只代表结构重要，不代表产品适合某个具体客户，所以仍需风险和金额过滤。

## 4. Louvain 社区发现

Louvain 想做的是：让社区内部连接尽量密，社区之间连接尽量疏。它通过优化模块度 `modularity` 形成社区。

输出中的 `communityId` 只是本次运行的社区编号，不表示等级高低，也不保证每次数据变化后编号不变。真正业务用途是：“和目标客户处在同一群体的人还喜欢什么”。

常见误区：

- 不能把社区编号当作客户价值分。
- 不能因为同社区就跳过合规适配。
- 社区可能随数据和参数变化，需要评估稳定性。

## 5. RAG、GraphRAG、混合检索

RAG 是 Retrieval-Augmented Generation，中文常译“检索增强生成”。先找资料，再让模型根据资料回答，减少只靠模型记忆猜测。

GraphRAG 把图结构也当作检索证据。这里的三路证据是：

- graph：相似客户的购买关系；
- community：同社区客户热度；
- vector：用户描述与产品描述的语义相似度。

混合检索的价值是互补：稠密向量擅长语义，BM25 擅长关键词，知识图谱擅长关系和路径。

## 6. Embedding 与向量

Embedding 是把文本转成数字列表。例如：

```python
[0.8, 0.2, 0.9, 0.3]
```

本项目 4 个维度依次代表安全、成长、流动性、收益偏好。真实项目可替换为 BGE 等模型，但可解释的 4 维版本适合学习和确定性测试。

```python
for a, b in zip(left, right, strict=True)
```

- `for`：逐个循环。
- `a, b`：每轮接收左右向量同位置的两个数字。
- `zip`：把多个可迭代对象按位置打包。
- `strict=True`：长度不同就报错，避免悄悄丢数据。

## 7. BM25 与稀疏向量

BM25 看重词频、词的区分度和文档长度。比如查询里明确出现“灵活”，包含该词的产品描述容易获得优势。它不同于稠密向量：BM25 更像精确关键词，稠密向量更像语义近似。

Milvus 中 `FunctionType.BM25` 会把 `description` 文本经过 analyzer 生成 `sparse_vector`，再对稠密和稀疏字段分别建立索引。

## 8. RRF

不同检索器的分数不可直接相加：余弦可能在 -1 到 1，BM25 可能大很多，图热度又是次数。RRF 只看排名：

```text
RRF分数 = Σ 1 / (k + rank)
```

- `Σ`：把每条召回通道的贡献相加。
- `rank`：该结果在当前通道的名次，从 1 开始。
- `k`：平滑参数，本项目用 60，避免第一名独占全部权重。

## 9. LangGraph State、Node、Edge

```python
builder = StateGraph(RecommendationState)
builder.add_node("vector_retrieve", self._vector_retrieve)
builder.add_edge("vector_retrieve", "rrf_fuse")
graph = builder.compile()
result = graph.invoke(input_state)
```

- `StateGraph`：类；用状态结构来搭工作流。
- `RecommendationState`：共享状态的字段合同。
- `builder`：变量；尚未编译的图构建器对象。
- `add_node`：对象方法；登记节点名和要执行的函数。
- `add_edge`：对象方法；规定一个节点完成后去哪里。
- `compile`：把图结构编译为可执行对象。
- `invoke`：给图输入，真正执行并返回最终状态。

## 10. NL2SQL / NL2Cypher 为什么需要闸门

模型可能生成删除、改表、无限量查询或访问未授权数据。安全流水线必须分离：

```text
自然语言
 -> 生成候选查询
 -> 语法/AST解析
 -> 只读检查
 -> 表或标签白名单
 -> 参数化
 -> 自动补LIMIT
 -> 数据库只读账号执行
```

参数化的例子：

```cypher
MATCH (c:Customer {customer_id: $customer_id})
RETURN c
```

`$customer_id` 是参数占位符，实际值通过独立参数字典传入；不要用字符串拼接把用户输入直接塞进查询。
