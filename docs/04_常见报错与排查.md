# 常见报错与排查

## 1. `docker API ... pipe ... cannot find the file`

含义：Docker 命令存在，但 Docker Desktop 引擎没运行。

顺序：打开 Docker Desktop → 等 Engine running → `docker info` → 再启动容器。不要改 Python 代码。

## 2. `Connection refused` 连接 7475、7688 或 19531

含义：对应端口没有服务监听。

```powershell
docker ps
Test-NetConnection 127.0.0.1 -Port 7688
Test-NetConnection 127.0.0.1 -Port 19531
```

先确认容器状态，再看日志：

```powershell
docker logs --tail 100 项目-neo4j-gds
docker logs --tail 100 项目-milvus-standalone
```

## 3. `Unknown function 'gds.version'`

Neo4j 启动了，但 GDS 插件没加载或版本不兼容。检查：

```powershell
docker exec 项目-neo4j-gds cypher-shell "RETURN gds.version()"
```

本工程固定 Neo4j 5.26 与 GDS 2.13 兼容组合。

## 4. `A graph with name ... already exists`

内存图投影名重复。`cypher/03_...` 开头已经使用：

```cypher
CALL gds.graph.drop('day3536_train', false)
```

重新从 03 文件第一行执行，不要只重复中间的 `project`。

## 5. `ModuleNotFoundError: day3536_homework`

常见原因：不在项目根目录，或没有 `uv sync`。

```powershell
Set-Location "./Day35_Day36_GraphRAG_Homework"
uv sync --python 3.12
uv run python -c "import day3536_homework; print(day3536_homework.__file__)"
```

## 6. 中文显示乱码

```powershell
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

文件右下角编码应为 UTF-8；修改后 `Ctrl+S`。

## 7. Milvus 插入成功但立即搜不到

原因可能是写入与检索可见性之间存在时序。本工程在 `insert_products()` 后显式调用 `flush()`。这是本次真实验收发现并加入的回归边界。

## 8. `AssertionError` 不是程序“坏了”

`assert 实际值 == 期望值` 表示测试合同不满足。读法：

1. 看最后一行错误类型和自定义消息；
2. 向上找自己文件的路径和行号；
3. 打印实际值；
4. 判断是代码、数据、环境还是测试期望错误；
5. 只修根因，完整重跑所有测试。

## 9. NL2SQL/Cypher 被安全模块拒绝

这是预期保护，不要直接绕过。检查是否包含写命令、多语句、未授权表/标签、`CALL` 或缺少 `MATCH/RETURN`。生成器和执行器必须保持分离。

## 10. PowerShell 脚本禁止执行

只对当前进程临时放开：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

然后再用 `& ".\scripts\脚本.ps1"`。不要随意修改整台电脑的永久策略。
